# 0.11.3 — detail

A defect release for installations without the confidential assurance store.

## Diagram refresh

Since B96 (0.11.1), `refresh_diagram` decided between re-rendering a diagram from its stored state and
reconciling its body with the model by asking the diagram's type whether its body is rendered from its
records. A type the installation does not register could not answer, so its diagrams fell through to the
ArchiMate reconcile, which resolved the type with the raising lookup.

The refresh now asks `diagram_body_is_reconcile_owned`, the question the verifier already asks, through
`diagram_sync._reconciled_from_the_model`. Only a type the catalog knows to be reconciled from the model
is reconciled; scope-bound, record-rendered, store-projected and unregistered-type diagrams are
re-rendered from stored state.

## Verification

`diagram_body_is_reconcile_owned` now answers "not reconcile-owned" for a type the catalog does not know.
It had treated such a diagram as owned when its `diagram-entities` was empty, which applied `E314`–`E318`
and `W307` to it.

## Test suite

The suite now runs as an installation without a store, matching CI. Its guards against the real
credential backend were fixtures, which start after collection; a test module that built the module
registry at import time could reach the developer's real store and register the assurance types for the
rest of its worker. The guards are applied when `tests/conftest.py` is imported.

Tests that need an empty store receive a copy of one initialised per process
(`tests/support/assurance_store_template.py`), and test processes derive a store key with one PBKDF2
iteration (`tests/support/store_key_derivation.py`). The product never sets the iteration count, so real
stores keep the library default.
