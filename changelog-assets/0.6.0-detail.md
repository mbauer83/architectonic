Maintainer-facing mechanism for the summary in `CHANGELOG.md`.

## One declaration, several drawings

### Colour and corner shape

The meta-ontology gains `element_appearance`: one colour per domain, and each corner style assigned
to element classes.

```yaml
element_appearance:
  domain_colors: { motivation: '#D1BADC', … }
  corner_classes:
    rounded:  [behavior-element, internal-behavior-element, strategy-behavior-element]
    diagonal: [motivation-element]
    square:   [structure-element, active-structure-element, …]
  de_emphasis: { toward: '#FFFFFF', amount: 0.55 }
  border:      { toward: '#000000', amount: 0.7 }
```

Corners are keyed on classes because entity types already declare them and the meta-ontology already
names them; nothing had to be re-classified. Borders and container tints are *derived* from the one
declared colour by the mix rules, so a palette cannot half-move.

The declaration is structural in the same sense `relation_notation` is: a corner style is
`diagonal`, never `motivation`. A renderer honours it without knowing the vocabulary, and the
resolved answer crosses the wire per entity type so a client never handles a class name.

The same fact lived in three places, disagreeing on every domain:

| domain | PUML generator | `domains.ts` | `GraphExploreView.helpers.ts` |
| --- | --- | --- | --- |
| motivation | `#EDD6F0` | `#d8c1e4` | `#d8c1e4` |
| business | `#FFFAC8` | `#f4de7f` | `#f4de7f` |
| application | `#CCF2FF` | `#b6d7e1` | `#b6d7e1` |
| implementation | `#FFE4C4` | `#f4c896` | *absent* |

The third was a truncated copy, so implementation elements fell back to grey in the graph explorer
while a diagram drew them peach. The frontend now takes colour, border, container tint and corner
style from `types.generated.ts`, generated from the ontology and held by the diff gate CI already
runs — the arrangement `routeTimeoutPolicy.json` uses. `domains.ts` keeps the *labels*: what a
domain is called is a presentation concern, what colour it is is not.

ArchiMate assigns no formal semantics to colour and defines no hex values, so there is no normative
palette these approximate. They are this product's declaration, which is the argument for stating
them in one place.

### A relationship's spelling is derived from its notation

`puml_arrow_for(notation)` is the single derivation, and a gate holds every connection type's arrow
equal to it. Fifteen of the catalogue's types disagreed before.

**`..` is dashed, not dotted.** `A ..> B` renders `stroke-dasharray:7,7`, identical to
`-[dashed]->`; a dotted line is `1,3` and needs `[dotted]`. `archimate-realization` therefore
declared dotted and drew dashed from the day it was written, and its declaration was corrected to
the drawing rather than the reverse.

`_archimate-relations.puml` is now generated from the same derivation, like the glyph and stereotype
includes. It was hand-maintained and defined nine macros for twelve relationships, so a body calling
`Rel_Composition`, `Rel_Aggregation`, `Rel_Assignment`, `Rel_Specialization` or `Rel_Flow` drew
nothing at all. All five direction variants of all twelve are generated.

### A body's copy of a declaration is a copy

The three generated includes have two storage forms. A body may keep the `!include` marker and have
it expanded at render time, or carry the expansion itself so the `.puml` renders anywhere; E303
accepts either, and every diagram in the shipped repository takes the second. That copy was
refreshed only as a side effect of regenerating the body, so an ontology change reached a diagram
only when something else rewrote it. Nine were stale:

| | |
| --- | --- |
| hand-laid-out, so sync keeps the body verbatim | 7 |
| generated, but with no content change to trigger one | 2 |

All nine still carried `Rel_Access(from, to, label) from ..> to` — the solid-over-dotted access
arrow corrected above — along with the previous palette and no corner declarations at all.

`ArchimateDeclarations.restated_in(body)` is the single reading and the single rewrite. It restates
what a body already declares and nothing else: a declaration the ontology does not make is left
alone, and layout, element lines and authored `skinparam` overrides are untouched, which is what
lets a manual-layout diagram be brought level without disturbing the picture its author ruled. The
write path restates on every edit, including the branch that leaves the body otherwise as it found
it, and `generate_static_includes --check` — already a CI gate for the include files — now reports
any stored body that disagrees.

`inject_includes` inserts the `!include` marker when a body has none, so it had to learn the two
cases apart: a body with no preamble gets one, a body that has one has it restated. Pointing the
first at the second produces two preambles, the second still stale.

### The same nine had no label width bound

`skinparam wrapWidth` is written by the same renderer into the same header, and a body that predates
it never received it. A PlantUML box is as wide as its widest unwrapped label, and a box wide enough
to hold its label on one line is a box one line tall — which is what made the cut corners hard to
read. Measured over the repository's 124 motivation elements:

| | height | width | straight side : corner |
| --- | --- | --- | --- |
| with the bound | 52px | 228px | 1.58 |
| without it | 38px | 331px, up to 548 | 0.89 |

`DiagonalCorner 10` cuts all four corners, so a 38px box spends 20px of each vertical edge on corners
and 18px on the side between them. A rounded corner at `RoundCorner 14` renders as a 7px radius, so
the two silhouettes converge. At 52px the straight side runs half again the corner and the octagon
reads as an octagon.

PlantUML cannot state a minimum height. Its 478 skinparameters offer `Padding`, which is deprecated
and draws *"Please use CSS style instead of skinparam padding"* into the image, and the style
property that message points at has no effect on these elements. The label bound reaches the same
place by the other route, and narrows the diagrams while it is there.

So the refresh is the renderer's, not the include module's: `GeneratedHeaderRefreshingRenderer` is
the capability, and a notation whose header states nothing generated answers by not implementing it.

Three readers of these same syntaxes in `diagram_builder.py` — the stereotype map, the sprite map
and the display block — were verbatim copies used by nothing, and are gone.

## Three renderers that lost content

### Sequence guards

`alt [features computed]` is valid PlantUML that means something other than it looks: a single
`[...]` is link syntax, `[target label]`. The guard rendered as a hyperlink whose target was the
first token, so the first word vanished. Measured:

| source | drawn |
| --- | --- |
| `alt [features computed]` | `computed` |
| `alt [timeout or unknown error]` | `or unknown error` |
| `alt features computed` | `[features computed]` |

A single-word guard round-trips through the broken form, so the loss is invisible in the common
case. The gate renders the generator's own output and reads the guard back out of the SVG, over
multi-word guards.

### Activity fork/join

A fork and a join are both entries in `diagram_entities.fork[]`; a fork has outgoing
`step-fork-branch` connections and a join has only incoming `step-flow`. The join therefore fell
through `if branches:`, emitted nothing, and the walk continued — and each branch was handed a
*copy* of the visited set, which is correct for independent paths and is exactly what made every
branch re-walk the tail. Two nested forks produced six copies of everything after the outer join.

A branch stops at the join; the continuation is emitted once, after `end fork`, by the fork that
opened it. A branch that never reaches the join is still drawn.

### Graph edge geometry

`edgePathFor` backed the line off at the target end only — the parameter was named `targetRadius` —
so every `marker-start` the ontology declares was drawn under the source node's own shape. The
assignment ball had never been visible. Both ends now back off by their own node's radius, and
`edgeEndRadius` derives the radii from `NODE_SHAPE_RADIUS`/`ANCHOR_HALO_RADIUS` rather than
restating them as `34`/`26` at the call site.

## Readings consolidated

### What a document's prose refers to

Four readings of one markdown link. The cascade-delete preflight matched `](….md)` with a regex of
its own, which cannot match `](….md#properties)` — so a document linking into a *section* of an
entity was invisible to the check whose job is to find what a deletion breaks. `references_from` is
the reading now and each caller is a filter over it. The register gained a row, which named a fifth
reader in the workspace migration; it was converted rather than exempted.

W155 already reported an unresolvable internal link and had only ever been asked about documents.
Pointed at diagram prose, it found 57 links in three matrix diagrams pointing at a layout that
predates `projects/<slug>/`.

### The graph explorer's edge set

Free exploration asked each node for its own connections and added exactly those. An edge between
two neighbours is incident to neither the focus nor any expanded node, so it was never requested.
`connections_among` in `diagram_selection` already stated the rule and `connection_to_dict` already
was the wire shape; `GET /api/connections/among` composes them, adding a third *caller* rather than
a third reading.

Across the twelve highest-degree entities in this repository, the first hop grows from the star to
the induced set by 1.4x to 3.5x — worst case 92 edges over 27 nodes. No filtering control is added
for that.

### Custom primitive resolution

`_resolve_primitive` scanned `classifiers_by_id.values()` and applied the scope check to the first
label match, so with two declarations sharing a label the answer and its stated reason depended on
dictionary iteration. It now resolves through `classifier_ids_by_name` — the index the projection
already builds and W333 already reads — enterprise first, then by id. The collision itself stays
W333's to report.

## Writes that dropped what they were given

Three of one shape.

* **Scratchpad version.** `save()` bumped the *caller's* in-document version, which the wire
  contract calls "read back and ignored here". A client omitting it drove the store backwards
  (measured `0.1.2 → 0.1.1`), after which every write reset to the same value and no writer was ever
  detected as stale. A save that stores what is already stored is no longer a write.
* **Scratchpad frames.** A read serves `permitted-domains`; the file stores `permits.domains`; the
  reader knew only the second. The canvas hands back what it read on every save, so a seeded
  scratchpad lost its frames' declarations at the first drag.
* **Matrix.** `create_matrix` upserted and wrote only what the caller restated, dropping the entity
  axes and connection-type configuration — which `artifact_create_matrix` had no parameter for, so
  no MCP caller could preserve them. `format_matrix_markdown` additionally wrote the axis pair only
  when the *row* axis was given.

## Model content

Two ids in a traceability matrix's `to-entity-ids` named outcomes that have never existed in this
repository, drawing two columns and four ticks. Of the matrix's 26 ticks, 22 had a model connection
behind them and every connection from a row was represented; the four without one were exactly
those two columns. One duplicated a real outcome the matrix omitted, so that column took the real identity and
kept its ticks; the other duplicated a column already present. The matrix is now an exact
projection: 24 ticks, every one backed, none missing.

`entity-ids-used` has been resolved against the registry since the beginning and the matrix axes
never were, so an axis could name anything indefinitely. Both are resolved now, at the same
severity.

55 dangling links in three matrix documents were repaired to where their targets live under
`projects/<slug>/`.
