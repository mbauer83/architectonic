# 0.11.4 — detail

A defect release. Nothing in it depends on the diagram editing work that follows.

## Proposed changes

A proposed change recorded one edit and `base-revision`, a hash of the whole target file. The hash says
that the enterprise artifact moved and not where. `change_rebase._classify` asked whether the target
exists, whether it already says what the change asks, and whether a replay verifies; a field changed
upstream to a third value passed all three.

A change now records `base-values`: for each field its edit names, what the enterprise artifact said
when that field was first changed. `integration_detection.fields_moved_upstream` names the fields whose
current value is neither the base nor the proposal, and the classifier reports them as `conflicting`
before attempting the replay. Revising or superseding a change keeps each field's first base. A change
with no base for a field replays without the comparison: that is every change written before this
release, and any written where the enterprise artifact could not be read. `E150` holds `base-values` to
the fields the recorded edit names. A document's `body` has no current reading and gets no base.

## Links and moves

`application/document_links.py` owns reading a document link and now owns relocating one.
`relocated_links(content, read_from, written_to, moves)` re-expresses each relative link from where the
text is read to where it is written, through a map of moved files, and keeps the anchor. A text that
moves and a text that stays are the same call with different arguments. Paths are compared lexically:
inside a batch the staging tree links live files in, and resolving a link through such a link found
nothing to rewrite. The rewriting that compared an href whole is removed.

## Batches

A batch is verified in a staged tree that takes in files as operations name them. The repository's
configuration directory is now staged when the tree is created, apart from the transaction storage:
directories are made and files linked, so a write is copied first. Document types, the group registry
and attribute schemata are read from it.

The batch's candidate store reads what the batch staged before what it superseded. Every touched file
is in the superseded set, so the previous order answered "absent" for anything just written.

`artifact_bulk_write` carries `batch_verification` on every path, including an idempotent replay and
`artifact_get_operation`. `summary` and `ids` carry the verdict, whether verification ran, the counts
and the findings; `full` carries the whole record. An issue's location names the live repository.

## Scratchpad lift

`ScratchpadRepositoryPort.require_version` asks the question `save` asks, through one comparison, and a
lift asks it before the model is written. The scratchpad the lift would leave is validated at the same
point. Once the model write has committed, a failure to record it is reported on a receipt that says
`committed` and carries every id.

A document note may hold a `realized` reference when it carries a document type. A `bound` reference
remains for elements.

## Assurance store

Whatever opens a store keeps a shared `flock` on `<store>.hold` from open to close. `init_store`,
`rotate_key` and the upgrade's restore take it exclusively for their whole run and refuse if they cannot.
The kernel releases a hold when its holder exits, so a leftover file blocks nothing and nothing removes
it. A writer that cannot establish the answer refuses; an opener on a filesystem without locks logs a
warning and opens.

## Gates

`tests/architecture/test_skills_name_only_what_is_registered.py` reads every skill and checks each tool
name, call argument, required argument and assurance relationship type against what is registered.
