# 0.12.1 — detail

Advice findings, purpose lines on diagrams and viewpoints, a persistent PlantUML process, and the security fixes
that remained after 0.12.0.

## Advice

`domain/verification_findings.py` holds three severities and the one statement of the code shape (`CODE_PREFIX`:
`E`, `W`, `A`; `RULE_CODE`; `severity_of_code`), which the rule-code register test reads. Severity tallies are an
exhaustive match; only `error` makes a file invalid or blocks a write. The server decides presentation once from
the element's status (`presentation_for`): draft and deprecated give a marker, active gives a listed entry.
`artifact_verify` reports advice apart from the per-file results (`counts.advice`, `counts.advice_by_status`, and
an `advice` list holding active elements' advice in summary mode and all of it in full mode); the promotion plan
carries an `advice` field; the entity read and context serve `advice: {presentation, open, accepted}`.

Accepting an advice writes `accepted-advice: [{code, reason}]` into the entity frontmatter through the ordinary
entity edit vocabulary (`accepted_advice`); an omitted value keeps the stored set and `[]` clears it. A warning or
error code, an unknown code, an empty reason, a reason over 280 characters and a repeated code are refused.

A341 (`application/verification/_ordered_sequence_rule.py`, core in `domain/relationships/ordered_sequences.py`)
reads three ontology declarations and names no type: `denotes_ordered_sequence` on the entity type (ArchiMate:
process and value stream), composition as containment with `exclusive_target`, and order as relations whose
`derivation_role` is `dynamic` (exactly triggering and flow). Two parts are ordered when a path of ordering
relations runs from one to the other through any elements, since a chain of dynamic relations derives one between
its ends. The repository pass reads outgoing files through `parse_outgoing_file` and uses the candidate repository
for point lookups only.

## Purpose lines

`domain/purpose_lines.py` owns the shape: `stakeholders` and `concerns`, each a list of prose strings or
`{ref: <id>}`; a viewpoint's earlier free strings read as prose, so no stored file changes. Which entity types a
reference may name is declared per ontology (`purpose_line_elements`) and served to the GUI through the write-help
read (`purpose_line_entity_types`). Resolution is one check (`application/verification/purpose_line_references.py`)
used by the diagram verifier (E185 unreadable list, E186 missing element, E187 type not admitted), by
`persist_viewpoint_definition` (refusing `unknown-purpose-reference` and `purpose-reference-type-mismatch`) and by
the promotion plan, which resolves against the enterprise after promotion (`promote_closure_scope.py`) and reports a
dangling reference as a missing dependency of kind `purpose_line_reference`.

A diagram inherits each list its viewpoint states unless it states that list itself; the read reports
`inherited_from`. `GET /api/diagrams?stakeholder=` takes an id or words. W183 compares a stored diagram's type with
the viewpoint's `representation_types`.

## PlantUML

`infrastructure/rendering/plantuml_runner.py` owns running PlantUML; `plantuml_process.py` is one long-lived
`-pipe` process per launch (format, resolution, size limit, jar, dot, java) with a random delimiter. Only a body
with exactly one start/end block goes to the live process; anything else takes a one-shot run. A process that dies
between renders is replaced, one that dies mid-render is replaced and the render retried once, a render past its
deadline kills the process, and an idle process stops after 300 s. The long-lived JVM runs with the serial
collector. The syntax check draws through an application-layer port. A fitness test refuses any other module that
runs the jar. Over the committed diagrams the SVG, PNG and syntax-check outputs are byte-identical to the
per-render ones.

## Title search

`application/artifacts/title_match.py` owns the title tiers: exact, the title begins with the query (the last
word may be unfinished), every typed word begins a title word, the query occurs in the title (three or more
characters). `_ranking.rank_hits` orders those tiers above every score, across kinds, before the scored and
round-robin section, so neither bm25 nor the fused vector branch moves a typed title out of the window. The fts5
query makes the last word a prefix (`"tok"*`), and each kind's per-table cut admits rows by title match first,
shortest title first among titles that begin alike (`artifact_index/_sqlite_search.py`; `KeywordRow`,
`TitleAdmission` in `domain/search_records.py`), which also survives the engagement/enterprise merge. Typing every
self-model name character by character, the search bar's stable p90 went from 18 characters to 6 (keyword) and 7
(fused); a name now reaches the window at its shortest unshared prefix. The relevance suite gains a `typed`
stratum and two live-content invariants (an exact name ranks first among its namesakes; the shortest unshared
prefix of a name ranks it first).

## Fixes

- `DiagramReplacement.stated_viewpoint()` passes the viewpoint to the edit only when the request stated it.
- `ui/lib/clipboard.ts` falls back to a selected text area outside a secure context; an ESLint rule refuses
  `navigator.clipboard` elsewhere.

## Security

`GitCredentials.https_origins` holds the `scheme://host[:port]` origins the HTTPS credential was collected or
verified for (`credential_origins`, in `git_auth` with the other remote-URL readers); `git_askpass.build_git_env`
passes them as `ARCH_GIT_CREDENTIAL_ORIGINS`, and the helper answers a username or password prompt only for a
listed origin and gives the SSH key passphrase only to ssh's passphrase prompt.

`config/git_identity.py` is the one source of the identity the backend acts as, for commits
(`commit_with_identity`, which also overrides `GIT_AUTHOR_*` in the process environment) and for recorded
judgements (`recording_identity()`). `classification.record_tlp` returns a record's stored level or none, and
none ranks as `TLP:RED` in the exposure policy, the GSN draft's publishability check, the promotion preflight,
vulnerability impact, security metrics and E511.

## Tests and CI

The CI lint job refuses to shard the backend suite when more than a tenth of the collected tests have no recorded
duration (`tests/support/shard_durations.py`). The browser suite runs in three Playwright shards over one GUI
build, with the Playwright browser and the PlantUML jar cached.
