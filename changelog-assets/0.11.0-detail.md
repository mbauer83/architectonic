# 0.11.0 — detail

Maintainer-facing mechanism for the summary in `CHANGELOG.md`.

---

## The icon artifact and its one stored form

A library icon is `diagram-catalog/icons/ICO@<epoch>.<random>.<slug>.md`, written and read only by
`src/domain/icons/icon_file.py`: frontmatter, then the stored PNG as a fenced `png-base64` block and,
for an SVG upload, the sanitised SVG as a fenced `svg` block. It is a first-class artifact kind —
`artifact_location.artifact_kind_at` knows it, the index holds it in its memory store, the verifier
checks it (`E360`–`E363`, `W360`) — and it is group-less, so a group rename never moves one.

`src/infrastructure/icons/normaliser.normalise_upload` is the only way an upload becomes a stored
picture. A raster is decoded by Pillow with its decompression-bomb limit, refused above 1 MB or
4096 px, fitted into `render_form.STORED_BOX` (128 px high, 384 px wide) and re-encoded without
metadata. An SVG is parsed with `defusedxml`,
rebuilt element by element from an allow-list (`_svg_allow_list.py`) — no scripts, event
attributes, `foreignObject`, external `href` or `url()` other than a fragment reference, and a
`<use>` only within the document — with class styles inlined, then rasterised by `resvg` in a child
process started with `-I`, an empty working directory and a minimal environment. The result is a
PNG at most 32 KB; its `render-digest` is the SHA-256 of those bytes.

## How large an icon is drawn

Every size is an `IconBox` — a height and a maximum width — and a picture is fitted inside it, keeping
its shape: scaled to the box's height unless that would run wider than the box. The stored form is
fitted into `STORED_BOX`; the ArchiMate badge into 20 × 60 px (the type glyph's height), the figure
into 64 × 160 px, and the C4 sprite into 48 × 120 px. Sizing by the longer edge, as a single number,
drew a 4:1 wordmark as a 5 px strip in a badge; three times the height is room enough for one.

## Which icon an element shows

`src/application/icons/effective_icons.py` owns the precedence and reads the statements:
`display_icons` per instance id, `type_icons` per type or specialization name (the viewpoint
vocabulary, matched against `type_and_specializations`), then a specialization's `notation.icon`
where it names an `ICO@` id. An icon whose `applies-to` does not admit the element is passed over.
The ArchiMate and C4 renderers take an `icon_source` and draw through
`rendering/drawn_element_icons.element_icons`; the editor asks `POST /api/icons/preview`
(`application/icons/shown_icons`), which uses the same function. Renderers declare the styles they
draw through `IconPresentingRenderer.icon_styles`, read everywhere by `icon_styles_drawn_by`.

The names an element answers to, most specific first, are `domain/icons/element_names`: its
specializations, its type, then the type the notation draws it as where that differs (a model entity
drawn as a C4 container). The C4 renderer, the ArchiMate instance restatement and the preview read it.
The preview is given the diagram type and asks that type's own projection (`project_view_for_preview`)
what each entity is drawn as, and answers it as `drawn_as`, so the editor names no C4 type of its own:
the picker's *All ‹type› here* is the type the picture draws. Rows
register their instances with `useDiagramIcons` rather than being handed to it as a list, so the C4
editors' own rows are asked about like the entity list's.

## Where an icon is used

`application/icons/icon_usage.library_usage` reads a repository's diagrams and specialization catalogue
once and answers both questions asked of it: `users_of(icon)` — the diagrams naming it at either level
and the specializations defaulting to it — and `shown_for(element)`, the library icons diagrams state
for that element's own instance. `icon_users`, which the delete refusal and the replacement read, is
the first of these. REST `IconSummary` and the `artifact_query_icons` rows carry `used_on` (id and
name) and `default_for`; listed icons carry `shown_for_element`, which the picker orders by.

## Embedding

`src/application/puml_icon_header.py` writes and reads the block between `' arch-icons:begin` and
`' arch-icons:end`: one `!$ARCH_ICON_<first 12 hex of the digest> = "data:image/png;base64,…"` per
picture the body references. Declarations show `<img:$ARCH_ICON_…{scale=…}>`; C4 passes
`$sprite="img:$ARCH_ICON_…{scale=…}"`. The block is rebuilt from the references on every write. The
directive policy allows an icon variable only where the same body's block assigns it an embedded
image, so the 0.10.1 restriction to `data:` images holds unchanged. A kept (hand-laid) ArchiMate body
is re-pictured in place by `archimate_instance_icons.restate_instance_icons`; a figure's declaration
is restated whole.

## Writes

- `artifact_write/icon.py`: create (dry run normalises and verifies without writing), edit (the
  picture is not editable; an `applies-to` change is refused while `icon_usage.uses_outside` reports a
  use it would lose), delete (refused while `icon_usage.icon_users` is non-empty).
- `icon_replace.py`: every user diagram is rewritten through `edit_diagram(dry_run=True)`, and the
  diagrams plus the icon's deletion commit as one `commit_file_changes` transaction.
- `icon_share.py`: the diagram's stored picture goes through the create path; the icon is written
  first and the diagram edited after, because that edit is verified against the library. A refused
  edit deletes the icon. `ArtifactVerifier.with_icon_library` lets the edit resolve an icon the index
  has not yet been told of within the same operation.
- A diagram's own icons are prepared by `diagram_icons.prepared_local_icons` on every write, and by
  the GUI's composition before a preview, which drew library icons only before.
- Promotion: `_promote_icons.icons_a_promotion_carries` answers the icons to copy and those the
  enterprise holds by digest (`icons_held_by_picture`), planned over added diagrams and diagram
  conflicts alike; the promoted file is rewritten by `rewrite_promoted_frontmatter`, shared with the
  viewpoint re-pin.

## Request size

`RouteRow.max_body_bytes` (default `DEFAULT_MAX_BODY_BYTES`, 16 MiB; 2 MiB for `icons_create_icon`)
is applied by `backend/request_body_limit.RequestBodyLimit`, an ASGI middleware outside the
application's own. A declared `Content-Length` over the limit is refused unread; a chunked body is
counted as it is received. The refusal is `413 request_too_large` with `max_body_bytes` in its
details, rendered by `error_responses.api_error_response`. `route_policy.row_for_request` now matches
every request to its row by method and path, with literal segments ranked over parameters; the
cache-directive middleware used to match by path alone, so a write could take a read's `no-cache`.

## Backend fixes

- `server_roots.resolve_server_roots` resolves both roots. The index records absolute paths, so a
  relative root made `is_relative_to` fail in promotion and `scope_for_path` answer `unknown`.
- `_lifecycle_cli._stop_for_restart` treats `foreign_workspace` as nothing of this workspace's to
  stop.
- `m4_transaction._atomic_install` creates its temporary file with `os.open(…, 0o666)` instead of
  `tempfile.mkstemp`, which made every installed file 0600 regardless of the umask.
- Container: `docker/entrypoint.sh` writes `storage.read_model.semantic_search` from
  `ARCH_SEMANTIC_SEARCH` when it is set, then, when the setting is on (asked of
  `storage_read_model_semantic_search`), runs `get-embedding-model` into the `arch-models` volume at
  `/app/models`. The image does not fetch the model.
- `backend_start_lock.backend_start_lock`: an `flock` on `.arch/backend-start.lock` held from the
  endpoint plan until the spawned backend serves, by `ensure_backend_running`, `arch-backend --daemon`
  (around the pre-start guard, the plan and the spawn) and the updater's `start_backend`; never by the
  foreground server, which a holder spawns. A waiter re-plans and attaches; after
  `START_LOCK_WAIT_SECONDS` (twice the startup deadline) it fails naming the holder's pid. Before
  this, a backend indexing and not yet listening was `unhealthy_backend` to a sibling's guard, which
  refused to start.
