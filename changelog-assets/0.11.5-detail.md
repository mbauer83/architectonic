# 0.11.5 — detail

A defect release for repositories with more than one writer.

## What counts as repository content

Four places each stated which paths are repository content, and they disagreed. The pull, the content
diff and the sync status named `model/`, `docs/` and `diagram-catalog/`; the step that stages a save
took everything except runtime state. A repository in the grouped layout keeps entities under
`projects/<group>/model/`, every repository keeps scratchpads under `scratchpads/`, and configuration
lives under `.arch-repo/`.

`repo_layout.RUNTIME_STATE` now declares what is not content: `.arch/`, `.arch-repo/transactions/`,
`.arch-repo/sync-worktrees/` and `.arch-repo/exchange-identity.json`. Everything else is content.
`_git_command.CONTENT_PATHSPEC` states that for git, and the stager, `has_uncommitted_changes`,
`GitSyncManager._is_clean`, the content diff against upstream, `compute_sync_entries`, the repair and the
checkpoint clean all use it. One pathspec answers both "content in the working tree" and "content in a
given commit".

`batch_transaction._MANAGED_SUBTREES` is a different statement — what a staged write may touch — and is
unchanged.

## Pull

The pull moved the branch to the fetched commit and wrote only three directories into the working tree.
It now installs every content path the commit changes. The diff is taken with `--no-renames`, since a
rename was otherwise dropped. Before anything is written, the publisher refuses if a file it would
install holds uncommitted content (`LocalWorkInTheWay`, reported as `sync_conflict`).

The engagement rebase path ran `rebase @{u}` in a detached worktree, which has no upstream, so a
repository holding a local commit failed every pull. The pull of such a repository now completes.

`.arch-repo/.gitignore` is content: one writer lists the declared runtime entries, and it is written when
a repository's defaults are established, so it is tracked from the start.

Not covered: a file whose type changes upstream, and symbolic links, are still left out by the pull.

## Validators

A scratchpad save does not move the model generation, deliberately: a canvas saves continuously, and
moving it would invalidate every model read. Reads whose answers include scratchpads or references from
scratchpads were validated by the model generation alone. The index now publishes two further
validators, one for reads that show scratchpad references and one for reads that return scratchpads,
and the entity reads, the artifact read and the searches use them. A scratchpad save that changes no
reference does not move the first.

## Publishing

Only a save pushes. The sync status carries no count of commits an engagement repository is ahead of its
remote, and a push that is refused leaves the commit in place with no way to retry it from the page.
This release does not change that.
