# 0.2.1 — detail

The short version is in [`CHANGELOG.md`](../CHANGELOG.md). Nothing the product serves changed in this
release: the diff is a coverage configuration block, two test fixes, one new test, the gate list, and a
fitness function over it.

`0.2.0` was tagged against a CI run that went red. Two of its jobs failed, both for real reasons, and
both were reachable locally — nobody had run the commands that would have shown them. That is the actual
defect this release is about; the three fixes below are its symptoms.

## Why the gates did not catch it

`AGENTS.md` listed eight quality gates. `.github/workflows/ci.yml` runs nineteen. The nine that were
missing:

| Missing gate | What it checks |
| --- | --- |
| `npm run test:coverage` | the per-directory coverage thresholds in `vite.config.ts` |
| `uv run tools/docs/generate_mcp_docs.py --check` | generated MCP docs match the registered tools |
| `uv run python tools/docs/check_doc_links.py` | documentation links, anchors, media references |
| `uv run tools/ontology/generate_types.py` + `git diff --exit-code` | committed frontend types are the ontology's output |
| `generate_static_includes … --check` | generated diagram includes match the ontology |
| `check_licenses.py --ecosystem python --check` | no denied/unknown/unacknowledged Python licence |
| `check_licenses.py --ecosystem npm --check` | the same for npm |
| `generate_notices.py --check` | `THIRD-PARTY-NOTICES.md` regenerates identically |
| `coverage report` (combined shards) | the backend coverage ratchet |

The worst of these is the first, because the documented command and the CI command differ by one word.
`npm test` and `npm run test:coverage` run the same 1600 tests and print the same green summary; only the
second applies the thresholds. Running the documented gate produced a green result that meant less than
it appeared to.

`tests/architecture/test_local_gates_match_ci.py` now parses the workflow, reduces each command to the
token that identifies it — the npm script name, the tool path, the module — and asserts that token
appears in `AGENTS.md`. Provisioning (`uv sync`, `npm ci`, `arch-assurance unlock`) is enumerated as
setup and exempt; flags are deliberately not compared, so CI can shard pytest or hand eslint a
concurrency without the document having to track its parallelism. What it refuses is a gate existing in
one place and not the other.

## The three defects behind it

### Six type-level contract files were counted as uncovered source

`vite.config.ts` excluded `src/**/*.test.ts` from coverage. `*.test-d.ts` — the type-level contract
assertions added during 0.2.0 to hold the effect decoders against the generated OpenAPI types — did not
match that pattern. They are checked by `vitest --typecheck` and never executed, so each one was a
0%-covered file inside `src/domain/**`, and six of them took the directory from about 90% to 71.9%.
All four thresholds failed with no production code having changed.

Excluding them left branch coverage at 79.62% against a floor of 80. That part was real: `errors.ts`
was at 0%, its two exported helpers — `isRetryable` and `viewpointReferencedDetails`, both pure
narrowing logic over the error envelope — having no test at all. They have one now, which is the
honest way past a floor.

This is the same shape as the note already in `vite.config.ts` about nyc's extension list: two lists
that have to agree, one written without the other in view.

### A test bound one address and connected to another

`devProxyTimeout.test.ts` starts a real Vite dev server so the proxy under test is the one that ships.
It passed `port: 0` expecting an ephemeral port — Vite treats 0 as unset and falls back to 5173 — and
left `host` unset, so the server bound `localhost`. On a GitHub runner `localhost` resolves to `::1`
first; the test then fetched `127.0.0.1` and got `ECONNREFUSED` from a server that had started
perfectly well on an address it was not asking for. Locally `localhost` is IPv4 and it passed.

Fixed by pinning `host: '127.0.0.1'` and building the URL from what `httpServer.address()` reports, so
the bind address and the connect address cannot disagree.

### A regression test was failed by other tests' garbage

`test_a_closed_index_emits_no_unclosed_database_warning` arms `simplefilter("error", ResourceWarning)`
and calls `gc.collect()`. That collects the whole process: a connection leaked by any earlier test in
the same worker is finalised on *that* call, arrives through `__del__` as an unraisable exception, and
is attributed to whichever test is running. Under CI's `pytest-split --splits 2` the shard holds a
different slice of tests than a local full run, five foreign connections came due there, and the test
failed for a leak it neither caused nor could fix.

It now drains pre-existing garbage before arming the filter, which is the correct scope for what it
asserts — that *the index it closed* is silent. The foreign leaks are real and remain worth chasing;
the test that finds them has to be one that owns them.

## Known, not fixed here

- `test_combined_artifact_view_concurrency.py` asserts concurrency by wall clock
  (`_SEQUENTIAL_THRESHOLD = _DELAY * 1.6`, so 0.24s). Under a saturated 16-worker shard on a loaded
  machine two 0.15s calls took 0.41s and it failed; alone it passes in 8.7s, and both CI shards passed
  it. A timing assertion under xdist saturation is inherently load-dependent — the durable fix is to
  observe overlap rather than elapsed time, which is a change to what the test measures and not
  something to slip into a patch release.
- The five leaked sqlite connections named above.

## The e2e gate now defaults to what ships

`playwright.config.ts` defaulted `baseURL` to `http://localhost:5173`, a Vite dev server. That made
`npm run test:e2e` mean two different things: with no dev server up it failed its own preflight and read
as a broken environment, and with one up it passed against whatever the dev server was holding rather
than against a bundle anything had built. CI never took either path — it sets
`E2E_BASE_URL=http://localhost:8000`, where `arch-backend` serves the built SPA.

The default is now `:8000`, so the documented command and CI's command are the same one, and iterating
against a dev server is the opt-in (`E2E_BASE_URL=http://localhost:5173`). `npm run media` had already
defaulted to `:8000` on the same reasoning — a figure has to show shipped code — which is the argument
the smoke suite should always have been making too.
