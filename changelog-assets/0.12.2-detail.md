# 0.12.2 — detail

A fix for containers that are started more than once, and a release workflow that does not run CI twice.

## `arch-init` and the files it generates

On every start the container entrypoint runs `arch-init`, which regenerates the diagram include files
(`diagram-catalog/_archimate-*.puml`) in both tiers. An enterprise repository whose committed copies were older then
showed those files as modified, and the next `arch-init` refused the repository as having uncommitted changes, so every
second start of the container exited and was restarted again. The repository layout now declares the generated
include files (`domain/repository/repo_layout.py`), the git path filters answer the clean-tree question without them
(`infrastructure/git/_git_command.py`, `git_repository_state.py`), and `arch-init` asks that question; a change to any
other file still refuses. `tests/tools/test_arch_init_accepts_its_own_includes.py` holds it.

## Release workflow

`release.yml` first looks for the `ci.yml` run a push to `main` made for the tagged commit (event `push`, branch
`main`, `head_sha` the tagged commit), waits up to 45 minutes while it is in progress, and passes its verdict on. It
calls `ci.yml` on the tag only when there is no such run or it did not succeed; the publish job needs one of the two to
be green and does not run after a cancellation. `tests/architecture/test_release_waits_for_ci.py` holds the shape.
