# 0.8.0 — detail

Maintainer-facing mechanism for the summary in `CHANGELOG.md`.

---

## Reading a diagram without changing it

Colouring and printing are an *ad-hoc reading*, and the decision that shapes everything else is that a
reading is momentary: it lasts a visit to a diagram's page and is written nowhere. Not to the diagram,
not as a viewpoint, and not to browser storage — the last is worth stating because it is the obvious
place to put it and would quietly turn a situative reading into a preference that follows the reader to
the next diagram.

So a lens is a query parameter and nothing else. The server applies it to the PUML body's element
lines through the module that owns reading and writing an alias declaration, and hands back a picture.
Because it is a body transformation rather than a rendering flag, the download route can render the
same body and export exactly what is on screen — the two routes share the composition rather than
agreeing by construction.

Which of two colourings applies — one colour per member, or a gradient — is the model's answer, and it
is now given once. It was asked of the viewpoint criteria snapshot, whose enum map answers a different
question: what *string* values a condition may compare an attribute against. That map withholds a
boolean's two members deliberately, because a criteria condition on a boolean carries a real `bool`.
The attribute panel gives a boolean two members. A boolean entity attribute would therefore have been
offered two swatches and drawn as a two-colour ramp, with nothing failing. No entity attribute is
declared boolean today, which is exactly why it would have shipped.

## The legend

A legend is the only way a diagram can explain itself *inside the image*, which is what makes it
export with an SVG or a PNG rather than living beside them in a web page. It is a creole table because
the marks are separable: a reader turns colour, shape, glyph and arrow on and off independently, while
one drawn element carries all of its marks at once — so the marks cannot be shown by drawing elements.
A table's cells can each carry one.

Two things came from looking at the rendered picture rather than at a gate. The blank rows separating
sections rendered as bands of bordered nothing, because a creole table draws every cell border it has;
the bold heading row is what divides the sections, and the table is tighter without them. And the
arrows are drawn rather than described — an earlier row said "solid line, ball at the source, filled
arrowhead at the target", which makes a reader translate before they can match it to an edge. A corner
shape is the one mark still named in words: no character stands for "cut corners".

The relationship rows come from the *model*, not from the picture. A PlantUML arrow token cannot serve
as the notation authority — it has no form for a ball at the source — so reading one back would
describe several relationships identically.

## Activity loops, and what a drawing cannot carry

`repeat` / `backward:` / `repeat while` expresses a returning flow, and the renderer now emits it. What
it cannot express is refused with a reason: more than one step on the way back draws only the last,
measured, with a clean render and no warning.

Both halves of that decision live in one function over the declared graph, and the emission and the
verifier call it. The refusals were computed all along and discarded with a literal `[0]`, so a cycle
one step too long was not drawn, nothing said so, and the picture asserted that the flow falls through
— the opposite of what the model declares, with every step still present so the coverage rule saw
nothing wrong.

The graph's own construction moved to sit beside the graph. Three callers had been assembling it from
the renderer's privates — the golden-shape tests imported five underscored names to do it — and a
second assembly of a declaration is what this repository's syntax register exists to prevent.

## The step editor's two losses

The editor's outline is a tree, and a tree cannot draw an edge back to something above it. Two
consequences, both silent, both on content this repository ships:

A step two branches converge on was placed in both arms, because each branch walked with its own
visited set — fourteen placements for thirteen steps on the scratchpad diagram — so saving wrote it
into `diagram-entities` twice. Placing it once instead drops one of its two entry edges, which deletes
a branch of the flow. Neither is acceptable, so a branch whose first step is already placed carries a
rejoin marker: the step is written once, both edges that reach it are written, and the marker never
reaches the model.

A returning flow was dropped on every save, because a chain writes `step-flow` between consecutive
steps and an edge back to a step above has no consecutive pair to be written from. Opening a diagram
with a retry loop and saving it unchanged turned the loop into a straight chain.

Neither was visible from a test of reading or of writing alone. The round-trip test is what found
them, and it is stated over the real declarations of both shipped activity diagrams — which is how the
convergence case surfaced at all.

A third defect had the same root: the outline used one of the three tiers the renderer uses to choose
where to start, and tiers two and three exist for a graph that loops. A diagram whose steps all sit
inside a retry loop showed an *empty* outline for a picture the renderer draws in full. The two
implementations cannot call each other — the outline is rebuilt synchronously on unsaved state — so
they are held to one convention by a sample table both sides are checked against, the device the
style-token ramp already uses.

## Identity

Two files carrying one rename-stable stem are two artifacts claiming one identity, and every reference
spelled with it resolves to whichever the index keyed. The backend already refused to start on this.
Verification said nothing, so a rename that left the old file in place ran for a day at 0 errors and 0
warnings while the same content would have stopped the process.

Repository-level rules now run on every pass rather than only a full one: a rule asking whether two
files claim one identity is not answered by any file's own state, so a pass reusing that state
answered "clean" for a repository-level fault. Documents were already verified on the incremental
modes for that reason, and the same guard now carries the repository rules.

The first version of the rule reported every diagram that draws a diagram-only element as its own
duplicate — such an element's id is its diagram's with a compartment appended, so it shares the stem by
construction. The existing suite caught it, on a delete that had nothing to do with identity.

## Search

An exact title match ranks first across every kind of artifact rather than within one, and search
visibility is decided once so a full result window reaches the reader. A scratchpad is a record of its
own in the index rather than being reachable only through its notes, which is what made it findable by
its own name.

## Upgrade

**No migration.** The artifact index has no persisted form: it is an in-memory database rebuilt from
its schema on every process start, so the two tables this release adds arrive with it. There is no old
index file to open and nothing to convert.

Two diagnostics are new and both are warnings, so a repository holding an affected diagram continues
to verify: **W048** names declared step edges the drawing cannot carry, and **W049** names a returning
flow it cannot express. Each remedy is an authoring decision rather than a mechanical fix.

**E319 is an error**, and it is the one thing to look at on upgrade. It reports two files claiming one
rename-stable identity — a state the backend already declined to start on, so a repository that serves
today holds none. A repository that has never been served since a rename may.
