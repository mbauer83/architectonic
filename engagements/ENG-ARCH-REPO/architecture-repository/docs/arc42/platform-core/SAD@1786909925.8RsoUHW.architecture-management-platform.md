## Introduction and Goals

The Architecture Management Platform keeps an architecture model that humans and AI agents can both
read and change, in a form a machine can verify. The model lives as markdown files in git; every
write goes through the same verified pipeline whichever interface makes it.

The goals it is measured against are
[Sustain Unity of Effort at Agentic Velocity](../../../projects/motivation-narrative/model/motivation/goal/GOL@1780220699.FCfDuc.sustain-unity-of-effort-at-agentic-velocity.md),
[Maintain a Coherent, Traceable Architecture Model](../../../projects/motivation-narrative/model/motivation/goal/GOL@1712870400.Po1Qw3.maintain-a-coherent-traceable-architecture-model.md)
and
[Preserve Local Autonomy](../../../projects/motivation-narrative/model/motivation/goal/GOL@1784845186.L4Ceuf.preserve-local-autonomy.md).
The last two pull against each other, and the two-tier repository is the answer this architecture
gives.

## Architecture Constraints

What was fixed before any decision below was taken:

- **Files in git, not a database.** The repository is the source of truth and must stay reviewable,
  diffable and mergeable with ordinary tools —
  [Markdown File-Based Architecture Repository](../../adr/platform-core/ADR@1780761609.GQWvwi.markdown-file-based-architecture-repository.md).
- **Agents are a first-class producer**, not an add-on, following
  [AI-Assisted and Agentic Development as a Dominant Production Mode](../../../projects/motivation-narrative/model/motivation/driver/DRV@1776628131.GR9prv.ai-assisted-and-agentic-development-as-a-dominant-production-mode.md).
  Anything a human can do, an agent must be able to do through a typed tool surface.
- **Shared architecture must be machine-checkable** —
  [Keep Shared Architecture Explicit and Machine-Checkable](../../../projects/motivation-narrative/model/motivation/principle/PRI@1784845187.cM0Xea.keep-shared-architecture-explicit-and-machine-checkable.md).
- **Governance is proportional to impact and risk** —
  [Governance Is Proportional to Impact and Risk](../../../projects/motivation-narrative/model/motivation/principle/PRI@1784845187.E3_ttJ.governance-is-proportional-to-impact-and-risk.md).
  Engagement work is cheap to change; the enterprise baseline is not.
- **Assurance content is confidential by default** —
  [Assurance Content Is Confidential by Default](../../../projects/motivation-narrative/model/motivation/principle/PRI@1780655839.hVWaYW.assurance-content-is-confidential-by-default.md).

## Context and Scope

One system, with the people and systems around it:
[AMP — System Context](../../../diagram-catalog/diagrams/platform-core/CSC@1780829783.z8RRON.amp-system-context.puml).

Humans reach it through the GUI and the command line. AI agents reach it through MCP, hosted by an
[AI Agent Host](../../../projects/platform-core/model/application/application-component/APP@1780783991.v6AXNw.ai-agent-host.md)
outside the boundary. Two more systems sit outside it:
[Git Hosting](../../../projects/platform-core/model/application/application-component/APP@1780783992.Je9pmw.git-hosting.md),
which holds the repositories the platform synchronises with, and
[Supply-Chain Signal Sources](../../../projects/assurance/model/application/application-component/APP@1780783993.JqIBPJ.supply-chain-signal-sources.md),
from which vulnerability and SBOM signals are ingested.

Out of scope: the platform does not build, deploy or run the systems it models, and it is not an
issue tracker.

## Solution Strategy

Five decisions shape everything else.

1. **The repository is markdown files in git** —
   [Markdown File-Based Architecture Repository](../../adr/platform-core/ADR@1780761609.GQWvwi.markdown-file-based-architecture-repository.md).
2. **One backend authority; every write through the same verified pipeline** —
   [One Unified Backend Authority](../../adr/platform-core/ADR@1783406851.pGCuZn.one-unified-backend-authority-every-write-through-the-same-verified-pipeline.md).
   GUI, CLI and MCP are interfaces onto one write path, so no interface can produce a state another
   would have refused.
3. **A hexagonal core with a test-enforced dependency policy** —
   [Hexagonal Core with a Test-Enforced Dependency Policy; No Service Locator](../../adr/platform-core/ADR@1783406752.kQ__1X.hexagonal-core-with-a-test-enforced-dependency-policy-no-service-locator.md).
4. **Two tiers, with promotion as the governance gate** —
   [Two-Tier Repositories with Promotion as the Governance Gate](../../adr/promotion-and-tiering/ADR@1783406774.id7tSC.two-tier-repositories-with-promotion-as-the-governance-gate.md).
   This is how local autonomy and a coherent enterprise baseline coexist.
5. **A declarative ontology** — ArchiMate 4.0 as the shipped meta-ontology
   ([Adopt ArchiMate 4.0 Ontology](../../adr/platform-core/ADR@1783857340.Rax2QD.adopt-archimate-4-0-ontology.md)),
   with entity, connection and diagram types declared rather than coded, which is what
   [Extensibility and Configurability](../../../projects/motivation-narrative/model/motivation/principle/PRI@1712870400.uraDPR.extensibility-and-configurability.md)
   asks for.

## Deployment View

The platform is deployed two ways, and they are two views rather than one, because the topologies are
alternatives rather than layers — a picture holding both at once says the containers run in all of
those places at the same time.

[AMP — Deployment (Team-Serving)](../../../diagram-catalog/diagrams/platform-core/CD@1786912268.s4lI3nq.amp-deployment.puml)
is the shared installation: the backend and the GUI together in one app container, with each kind of
writable state on its own mounted volume.

[AMP — Deployment (Developer Workstation)](../../../diagram-catalog/diagrams/platform-core/CD@1787483149.XXyKn0T.amp-deployment-developer-workstation.puml)
is one person's machine, where the same four containers run directly from the
[Architectonic Source Distribution](../../../projects/platform-core/model/technology/artifact/ART@1787483097.xKVU0M3.architectonic-source-distribution.md)
against a working tree, with no image and no mounts. One component, two artifacts realizing it: which
of them a host holds is what makes it one topology or the other.

The infrastructure around them — the volumes that carry writable state, the endpoint they are reached
on, and the optional profiles:
[AMP — Team-Serving Infrastructure](../../../diagram-catalog/diagrams/platform-core/ARC@1786915465.u8ZGEhY.amp-team-serving-infrastructure.puml).

The [Team-Serving Deployment](../../../projects/platform-core/model/technology/technology-node/NOD@1782080479.7xNYBF.team-serving-deployment.md)
holds the
[Architectonic Container Image](../../../projects/platform-core/model/technology/artifact/ART@1786912186.j7ySGgZ.architectonic-container-image.md),
which realizes both the backend and the GUI — the SPA is built into the image and served from it, so
the two ship together rather than being deployed separately. That is why the deployment view shows
them inside **one** container: one
[Platform HTTP Endpoint](../../../projects/platform-core/model/technology/technology-interface/TIF@1786915451.cpBZx0u.platform-http-endpoint.md)
on port 8000 carries the GUI, the REST surface and MCP, and with it one healthcheck and one restart
unit.

Writable state is mounted rather than baked in, so replacing the image leaves it untouched: the
cloned repositories, the encrypted assurance store, the backend's own state and the credential vault
each arrive on their own volume. Two optional profiles sit beside the container — a
[TLS Reverse Proxy](../../../projects/platform-core/model/technology/technology-node/NOD@1786915451.yVcsZO4.tls-reverse-proxy.md)
for network access, and
[PocketBase](../../../projects/assurance/model/technology/system-software/SSW@1780656477.kIOyT2.pocketbase.md)
as an alternative assurance store backend.

The [Developer Workstation](../../../projects/platform-core/model/technology/technology-node/NOD@1712870400.4EFX7z.developer-workstation.md)
is the other shape, and the local-first one: the platform runs from source beside the repository it
edits. It holds the
[Git Repository](../../../projects/platform-core/model/technology/artifact/ART@1712870400.YsLpM8.git-repository.md)
and the [SQLite Database](../../../projects/platform-core/model/technology/artifact/ART@1712870400.FtioFJ.sqlite-database.md)
carrying the read model, and hosts the
[Python Runtime](../../../projects/platform-core/model/technology/system-software/SSW@1712870400.o7a0ad.python-runtime.md),
the [Git VCS](../../../projects/platform-core/model/technology/system-software/SSW@1712870400.T-zzVd.git-vcs.md),
the [PlantUML Engine](../../../projects/diagram-authoring/model/technology/system-software/SSW@1712870400.xVrBYD.plantuml-engine.md),
and [SQLCipher](../../../projects/assurance/model/technology/system-software/SSW@1780656477.nhzGvk.sqlcipher.md)
with the [OS Keychain](../../../projects/assurance/model/technology/system-software/SSW@1780656477.OCX11y.os-keychain.md)
for the encrypted assurance store.

Diagram rendering shells out to Java and Graphviz in both shapes, which is why the image carries a
headless JRE and why the render path is an arm's-length process call rather than a library import.

## Risks and Technical Debt

**Debt this architecture carries.**

- **Two persistence mechanisms.** Files in git for the model, an encrypted database for assurance.
  This is the price of the confidentiality boundary, and it means two backup stories, two upgrade
  paths and two places a reader has to look.
- **An external diagram toolchain.** Rendering shells out to Java and Graphviz. It bounds how fast a
  render can be, makes the image substantially larger than the Python application needs, and puts a
  GPL component in the build — inventoried in `THIRD-PARTY-NOTICES.md`.
- **Serialized writes are a throughput ceiling.** One writer at a time is what makes verification
  meaningful, and it is also the limit on how many agents can author at once.
- **The model is only as complete as it has been authored.** An element with no structural parent is
  reached by every projection as an outside neighbour and drawn as somebody else's — the model says
  nothing, and the diagram says something wrong. Coverage is a standing maintenance obligation
  rather than a one-time exercise.

**Risks this architecture does not remove.**

- [Autonomy at Agentic Velocity Threatens Unity of Effort](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1780220699.CK90bp.autonomy-at-agentic-velocity-threatens-unity-of-effort.md)
  — the two-tier split manages the tension; it does not dissolve it.
- [Assurance Disconnected From Architecture Loses Traceability](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1780655839.pZWwv1.assurance-disconnected-from-architecture-loses-traceability.md)
  — references are one-way by design, so the link holds only while the architecture side is kept
