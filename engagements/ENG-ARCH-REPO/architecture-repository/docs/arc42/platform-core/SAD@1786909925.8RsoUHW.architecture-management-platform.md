## Introduction and Goals

The Architecture Management Platform keeps an architecture model that humans and AI agents can both
read and change, in a form a machine can verify. The model lives as markdown files in git; every
write goes through the same verified pipeline whichever interface makes it.

The goals it is measured against are
[Sustain Unity of Effort at Agentic Velocity](../../../projects/motivation-narrative/model/motivation/goal/GOL@1780220699.FCfDuc.sustain-unity-of-effort-at-agentic-velocity.md),
[Maintain a Coherent, Traceable Architecture Model](../../../projects/motivation-narrative/model/motivation/goal/GOL@1712870400.Po1Qw3.maintain-a-coherent-traceable-architecture-model.md)
and
[Preserve Local Autonomy](../../../projects/motivation-narrative/model/motivation/goal/GOL@1784845186.L4Ceuf.preserve-local-autonomy.md).
The last two pull against each other, and the two-tier repository is the answer this architecture
gives.

It is written for the
[Architect](../../../projects/motivation-narrative/model/motivation/stakeholder/STK@1712870400.aB3dE1.architect.md),
the
[Developer](../../../projects/motivation-narrative/model/motivation/stakeholder/STK@1712870400.K9xTq2.developer.md),
the
[DevOps Engineer](../../../projects/motivation-narrative/model/motivation/stakeholder/STK@1712870400.4oprPM.devops-engineer.md)
and the
[Safety / Security Analyst](../../../projects/motivation-narrative/model/motivation/stakeholder/STK@1780655839.r4P3gy.safety-security-analyst.md);
the full stakeholder set is in the motivation model.

## Architecture Constraints

What was fixed before any decision below was taken:

- **Files in git, not a database.** The repository is the source of truth and must stay reviewable,
  diffable and mergeable with ordinary tools —
  [Markdown File-Based Architecture Repository](../../adr/platform-core/ADR@1780761609.GQWvwi.markdown-file-based-architecture-repository.md).
- **Agents are a first-class producer**, not an add-on, following
  [AI-Assisted and Agentic Development as a Dominant Production Mode](../../../projects/motivation-narrative/model/motivation/driver/DRV@1776628131.GR9prv.ai-assisted-and-agentic-development-as-a-dominant-production-mode.md).
  Anything a human can do, an agent must be able to do through a typed tool surface.
- **Shared architecture must be machine-checkable** —
  [Keep Shared Architecture Explicit and Machine-Checkable](../../../projects/motivation-narrative/model/motivation/principle/PRI@1784845187.cM0Xea.keep-shared-architecture-explicit-and-machine-checkable.md).
- **Governance is proportional to impact and risk** —
  [Governance Is Proportional to Impact and Risk](../../../projects/motivation-narrative/model/motivation/principle/PRI@1784845187.E3_ttJ.governance-is-proportional-to-impact-and-risk.md).
  Engagement work is cheap to change; the enterprise baseline is not.
- **Assurance content is confidential by default** —
  [Assurance Content Is Confidential by Default](../../../projects/motivation-narrative/model/motivation/principle/PRI@1780655839.hVWaYW.assurance-content-is-confidential-by-default.md).

## Context and Scope

One system, with the people and systems around it:
[AMP — System Context](../../../diagram-catalog/diagrams/platform-core/CSC@1780829783.z8RRON.amp-system-context.puml).

Humans reach it through the GUI and the command line. AI agents reach it through MCP, hosted by an
[AI Agent Host](../../../projects/platform-core/model/application/application-component/APP@1780783991.v6AXNw.ai-agent-host.md)
outside the boundary. Two more systems sit outside it:
[Git Hosting](../../../projects/platform-core/model/application/application-component/APP@1780783992.Je9pmw.git-hosting.md),
which holds the repositories the platform synchronises with, and
[Supply-Chain Signal Sources](../../../projects/assurance/model/application/application-component/APP@1780783993.JqIBPJ.supply-chain-signal-sources.md),
from which vulnerability and SBOM signals are ingested.

Out of scope: the platform does not build, deploy or run the systems it models, and it is not an
issue tracker.

## Solution Strategy

Five decisions shape everything else.

1. **The repository is markdown files in git** —
   [Markdown File-Based Architecture Repository](../../adr/platform-core/ADR@1780761609.GQWvwi.markdown-file-based-architecture-repository.md).
2. **One backend authority; every write through the same verified pipeline** —
   [One Unified Backend Authority](../../adr/platform-core/ADR@1783406851.pGCuZn.one-unified-backend-authority-every-write-through-the-same-verified-pipeline.md).
   GUI, CLI and MCP are interfaces onto one write path, so no interface can produce a state another
   would have refused.
3. **A hexagonal core with a test-enforced dependency policy** —
   [Hexagonal Core with a Test-Enforced Dependency Policy; No Service Locator](../../adr/platform-core/ADR@1783406752.kQ__1X.hexagonal-core-with-a-test-enforced-dependency-policy-no-service-locator.md).
4. **Two tiers, with promotion as the governance gate** —
   [Two-Tier Repositories with Promotion as the Governance Gate](../../adr/promotion-and-tiering/ADR@1783406774.id7tSC.two-tier-repositories-with-promotion-as-the-governance-gate.md).
   This is how local autonomy and a coherent enterprise baseline coexist.
5. **A declarative ontology** — ArchiMate 4.0 as the shipped meta-ontology
   ([Adopt ArchiMate 4.0 Ontology](../../adr/platform-core/ADR@1783857340.Rax2QD.adopt-archimate-4-0-ontology.md)),
   with entity, connection and diagram types declared rather than coded, which is what
   [Extensibility and Configurability](../../../projects/motivation-narrative/model/motivation/principle/PRI@1712870400.uraDPR.extensibility-and-configurability.md)
   asks for.

## Runtime View

**A write becoming a consistent, broadcast state** is the scenario that carries the most design:
[From a Write to a Consistent, Broadcast State](../../../diagram-catalog/diagrams/platform-core/SEQ@1781338373.XPtsGv.from-a-write-to-a-consistent-broadcast-state.puml).
A write is verified in a staging copy before it touches the repository, the read model is updated,
and connected clients are told what changed.

**Promotion** is the governance scenario:
[Promote Engagement Work to the Enterprise Repository](../../../diagram-catalog/diagrams/promotion-and-tiering/ACT@1781338474.NTuMXo.promote-engagement-work-to-the-enterprise-baseline.puml).
A selection is planned, its reference closure checked, and the whole plan refused before any file is
written if the selection would leave a reference dangling.

**Preliminary work** enters through the scratchpad and is lifted into the model rather than synced
with it:
[Working in a Scratchpad Area](../../../diagram-catalog/diagrams/platform-core/ACT@1786234873.w_H9LsR.working-in-a-scratchpad-area.puml).

## Deployment View

Two deployment shapes, and the model records both.

The [Developer Workstation](../../../projects/platform-core/model/technology/technology-node/NOD@1712870400.4EFX7z.developer-workstation.md)
is the local-first shape: the platform runs beside the repository it edits. It holds the
[Git Repository](../../../projects/platform-core/model/technology/artifact/ART@1712870400.YsLpM8.git-repository.md)
and the [SQLite Database](../../../projects/platform-core/model/technology/artifact/ART@1712870400.FtioFJ.sqlite-database.md)
that carries the read model, and hosts the
[Python Runtime](../../../projects/platform-core/model/technology/system-software/SSW@1712870400.o7a0ad.python-runtime.md),
the [Git VCS](../../../projects/platform-core/model/technology/system-software/SSW@1712870400.T-zzVd.git-vcs.md),
the [PlantUML Engine](../../../projects/diagram-authoring/model/technology/system-software/SSW@1712870400.xVrBYD.plantuml-engine.md)
that renders diagrams, and
[SQLCipher](../../../projects/assurance/model/technology/system-software/SSW@1780656477.nhzGvk.sqlcipher.md)
with the [OS Keychain](../../../projects/assurance/model/technology/system-software/SSW@1780656477.OCX11y.os-keychain.md)
for the encrypted assurance store.

The [Team-Serving Deployment](../../../projects/platform-core/model/technology/technology-node/NOD@1782080479.7xNYBF.team-serving-deployment.md)
is the shared shape: one long-lived container serving the GUI, the REST surface and MCP on port 8000,
with the repositories cloned into a volume and synchronised with git hosting. Two optional profiles
sit beside it — a TLS reverse proxy for network access, and PocketBase as an alternative assurance
store backend. The image is built in three stages: the SPA, the resolved Python environment, and a
slim runtime that keeps the source layout, because the application discovers PlantUML, its settings
and the built SPA by walking it.

Diagram rendering shells out to Java and Graphviz, which is why both are in the image and why the
render path is an arm's-length process call rather than a library import.

## Cross-cutting Concepts

**Identity.** Every artifact carries a typed epoch-random id that survives a rename —
[Artifact Identity](../../adr/platform-core/ADR@1783406715.vX4p7z.artifact-identity-typed-epoch-random-identifiers-in-filenames-grouping-by-directory.md).

**Verification.** One verifier serves every interface, and the write path runs it against a staged
copy before committing. Modelling conventions the verifier cannot express are written down:
[Motivation-Layer Modeling Conventions](../../standard/motivation-narrative/STD@1784345879.nNCIH_.motivation-layer-modeling-conventions.md).

**Diagram–model correspondence.** A diagram never silently changes the model; the correspondence is
an explicit binding —
[Diagram–Model Correspondence via Explicit Bindings](../../adr/platform-core/ADR@1783406738.Y7bzLM.diagram-model-correspondence-via-explicit-bindings-no-silent-model-mutation.md).

**Read model.** One canonical index per repository root, with a combined view for the pair —
[One Canonical Artifact Index per Repository Root](../../adr/platform-core/ADR@1783406811.fm8W_z.one-canonical-artifact-index-per-repository-root-a-combined-view-for-the-pair.md)
— on a single SQLite backend with copy-on-write concurrency —
[Read Model on a Single SQLite Backend](../../adr/platform-core/ADR@1783406825.9bDM6y.read-model-on-a-single-sqlite-backend-with-copy-on-write-concurrency.md).

**Failure semantics.** A failing profile is classified by blast radius and quarantined at a single
boundary —
[Profile Failure Semantics](../../adr/platform-core/ADR@1784674023.8alNxn.profile-failure-semantics-blast-radius-classification-and-single-boundary-quarantine.md).

**Response contracts** are owned by the server and generated outward, so a client cannot drift from
what the server sends —
[Response Contracts Are Owned by the Server and Generated Outward](../../adr/platform-core/ADR@1785451872.JiRXpP.response-contracts-are-owned-by-the-server-and-generated-outward.md).

## Risks and Technical Debt

The assessments this architecture is a response to, and which stay true whether or not it succeeds:

- [Centralized Governance Cannot Scale at Agentic Velocity](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1776628138.a6vxyj.centralized-governance-cannot-scale-at-agentic-velocity.md)
- [Autonomy at Agentic Velocity Threatens Unity of Effort](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1780220699.CK90bp.autonomy-at-agentic-velocity-threatens-unity-of-effort.md)
- [LLM-Based Agents Cannot Effectively Use Unstructured Architectural Knowledge](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1776628140.s68vVo.llm-based-agents-cannot-effectively-use-unstructured-architectural-knowledge.md)
- [Assurance Disconnected From Architecture Loses Traceability](../../../projects/motivation-narrative/model/motivation/assessment/ASS@1780655839.pZWwv1.assurance-disconnected-from-architecture-loses-traceability.md)

Known debt: diagram rendering depends on an external Java and Graphviz toolchain, which bounds how
fast a render can be and makes the image larger than the Python application needs; and the platform
carries two persistence mechanisms — files in git for the model, an encrypted database for
assurance — which is the price of the confidentiality boundary.

## Glossary

The terms this documentation uses in their platform sense, each backed by the business object that
defines it:

- [Entity](../../../projects/platform-core/model/business/business-object/BOB@1777229899.K8XxDs.entity.md) —
  one element of the model, in one file.
- [Connection](../../../projects/platform-core/model/business/business-object/BOB@1777293163.wDdrUY.connection.md) —
  a typed relationship between two entities, stored with its source.
- [Diagram](../../../projects/platform-core/model/business/business-object/BOB@1777230085.eGCeZq.diagram.md) —
  a view over the model, drawn from it or authored against it.
- [Document](../../../projects/platform-core/model/business/business-object/BOB@1777237431.55sMuE.document.md) —
  prose with a declared section structure, of which this file is one.
- [Engagement Repository](../../../projects/promotion-and-tiering/model/business/business-object/BOB@1712870400.so7gfN.engagement-repository.md)
  and [Enterprise Repository](../../../projects/promotion-and-tiering/model/business/business-object/BOB@1712870400.6Uok0b.enterprise-repository.md) —
  the two tiers.
- [Promotion Plan](../../../projects/promotion-and-tiering/model/business/business-object/BOB@1777390174.W5qfRD.promotion-plan.md) —

- [Scratchpad](../../../projects/platform-core/model/business/business-object/BOB@1786225252.hZy_6l1.scratchpad.md) —
