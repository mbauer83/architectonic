## Context

Some diagram types hold records of their own: a swimlane, a lifeline, a message, a classifier, a C4 container, an argument node. These are notation concepts that exist only in that kind of view, and each may be mapped to a model element. An [ArchiMate Diagram](../../../projects/platform-core/model/business/business-object/BOB@1777230117.IW_x2w.archimate-diagram.md) holds none: it is a view of the model, its membership follows the model, and synchronisation reconciles it against the model. Creating elements on the canvas raises the question of whether an ArchiMate element may exist only on a diagram.

Alternatives considered:

- **Allow a diagram-only ArchiMate element.** It would be absent from search, viewpoints, impact analysis, verification and every other diagram, and relations drawn to it would be relations the model does not have. One element type would have two populations that every consumer deciding by type would mix. Whether a diagram is model-owned is decided per diagram type, so declaring any such type would make every ArchiMate diagram hand-authored. Making the element real later would be a second promotion path beside the [Scratchpad](../../../projects/platform-core/model/business/business-object/BOB@1786225252.hZy_6l1.scratchpad.md)'s lift.
- **Keep ArchiMate diagrams views of the model, and meet the need another way** (chosen).

## Decision

A model ontology type is never hosted by a diagram. Diagram-held records stay reserved for types a diagram type owns. An element created on an ArchiMate canvas is a model entity in draft status: visible, verified, queryable, deletable, and shown as provisional on the canvas.

Three things serve what a diagram-only element would have been asked for. An element that is not settled is a draft. Thinking that is not ready to be typed belongs on a Scratchpad. A remark that means nothing in the model is a note on the diagram, free text with no type.

## Consequences

- Sketching on an ArchiMate canvas leaves draft entities in the model, which someone has to settle or delete.
- The ownership rule the [ArchiMate Diagram Type Module](../../../projects/diagram-authoring/model/application/application-component/APP@1795183439.VMFdVok.archimate-diagram-type-module.md) states is unchanged: its diagrams are model-owned.
- Diagram notes are a feature of their own, not yet built.
