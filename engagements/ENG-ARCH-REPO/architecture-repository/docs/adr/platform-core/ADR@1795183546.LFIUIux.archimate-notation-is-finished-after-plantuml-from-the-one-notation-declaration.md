## Context

PlantUML cannot draw all of ArchiMate's relationship notation. Serving and triggering come out with the same arrow, flow and influence with the same arrow, and assignment without its ball. The ontology's connection declarations state the true notation, and the graph explorer already draws from them, so the same relation looks different in two places. Element types are shown as a glyph in the corner of a rectangle; the specification also gives each type a shape of its own, and authors ask to choose per diagram.

Alternatives considered:

- **A native ArchiMate renderer**, as the [GSN Diagram Type Module](../../../projects/assurance/model/application/application-component/APP@1782027168.bARYLw.gsn-diagram-type-module.md) has. Full control, at the cost of a second layout engine and of rebuilding and keeping parity for every element, glyph, icon and specialization.
- **Leave PlantUML's notation and document the deviations.** Diagrams stay wrong, and the two surfaces keep disagreeing.
- **Correct PlantUML's picture afterwards, from the one declaration** (chosen).

## Decision

PlantUML draws the picture; the server then corrects what PlantUML cannot express. Each drawn relation's connection type is known, so its end decorations and line style are replaced from the relationship-notation declaration in the ontology. One drawer of relation decorations serves both this correction and the layout renderer of [Diagram Layout](ADR@1795183546.wFvjwyP.diagram-layout-optional-geometry-over-the-diagram-plantuml-stays-the-notation-the-server-renders-and-routes.md), so a relation looks the same in a laid-out diagram, an automatic one and the graph explorer.

Whether an element type shows as a corner glyph or as its official shape is a rendering option of the diagram. A diagram-type module declares the options it offers, with their types and defaults; the renderer reads the resolved values, and the GUI builds its controls from the declaration. Only the [ArchiMate Diagram Type Module](../../../projects/diagram-authoring/model/application/application-component/APP@1795183439.VMFdVok.archimate-diagram-type-module.md) names glyphs and shapes. An option is stored on the diagram and is an input to every re-render.

## Consequences

- Every existing diagram shows correct relation notation without being edited.
- The correction depends on the structure of PlantUML's SVG, the same dependency the layout reader has; an unrecognised structure leaves the picture as PlantUML drew it.
- A legend reflects the corrected notation.
- Rendering controls that were added by hand to individual diagram types move to the declared options.
- Not yet implemented.
