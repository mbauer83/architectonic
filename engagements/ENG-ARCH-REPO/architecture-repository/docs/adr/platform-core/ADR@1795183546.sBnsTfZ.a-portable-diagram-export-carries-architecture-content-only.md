## Context

A diagram can be exported as one self-contained file: the picture and its reader, usable without a backend. Such a file leaves every control the product has. It can be mailed, copied and kept, and nothing can revoke it. [Assurance Content Is Confidential by Default](../../../projects/motivation-narrative/model/motivation/principle/PRI@1780655839.hVWaYW.assurance-content-is-confidential-by-default.md), and [Assurance Diagram Outputs and Sources Are Classification-Gated](../../../projects/motivation-narrative/model/motivation/requirement/REQ@1781640247.cmI5m2.assurance-diagram-outputs-and-sources-are-classification-gated.md) already keeps confidential diagrams from being written as plaintext.

Alternatives considered:

- **Export any diagram up to a stated classification ceiling, stamped.** Serves both tiers, and one mislabelled node leaks. It needs a safety analysis of the export path that does not exist yet.
- **An encrypted export for confidential diagrams.** Key handling inside a static file protects less than it appears to.
- **Architecture content only** (chosen).

## Decision

A portable export may be made of a diagram of the architecture tier. A diagram type of the assurance module family is not exportable this way, whatever its classification. Styling derived from security signals is not carried into an export except under the stamped-banner rule that [Signal-Derived Styling Never Persisted](../../../projects/motivation-narrative/model/motivation/requirement/REQ@1784532460.n0Qwax.signal-derived-styling-never-persisted.md) already imposes on downloads.

The rule fails closed: a diagram whose type cannot be established as an architecture type is refused.

## Consequences

- Assurance users have no portable export. Widening the rule to a classification ceiling is a later decision that depends on an analysis of the export path.
- The export needs no handling of keys or classification labels, and its argument is short.
- Not yet implemented.
