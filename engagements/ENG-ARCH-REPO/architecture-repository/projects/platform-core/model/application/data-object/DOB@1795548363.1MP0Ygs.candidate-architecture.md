## Candidate Architecture

A named alternative change to the architecture, written deliberately with a rationale. It holds the operations it proposes, each with the base it was written against, the model elements it is read over, the candidate it stacks on if any, and where it stands in the work: draft, candidate, integrated, rejected or superseded. It is held beside the model and reaches the model only when it is applied.

## Notes

Whether each operation still applies is computed on every read against the model as it is then, and is not stored here. A rejected candidate is kept as a considered alternative.
