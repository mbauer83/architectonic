## Artifact File Store

The git-backed markdown repository the platform reads and writes: the source of truth for every artifact — entities, connections, diagrams, documents and scratchpads alike.

## Properties

| Attribute | Value |
|---|---|
| Backup and Recovery | Recovered by cloning from the git remote; a lost working tree costs only unpushed commits. |
| Consistency Model | Single-writer |
| Retention | Full history retained indefinitely: every version of every artifact is a git commit, and nothing is pruned. |
| Source of Truth | Authoritative |

## Notes

The platform's primary data store, and an application component because that is what a store is at this layer: a deployable unit of software that is the source of truth for data objects. Its file on disk is the Git Repository artifact, its engine is Git and the file system service, and the information it holds is the entity, connection and document data objects.

Named for artifacts rather than the model because the repository holds more than one: `model/` is a sibling of `docs/`, `diagram-catalog/` and `scratchpads/`, and *artifact* is the umbrella this product already uses for all of them — the same word as Artifact Index Store, which indexes exactly what this one holds.

C4 counts a data store as a container of the system that owns its schema, and this repository's format is the platform's own. Without an application-layer element there was nothing for a container view to draw, so the system's most important asset was absent from the diagram that exists to show it.
