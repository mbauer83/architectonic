## Staged Write Transaction Manager

Coordinates staged, all-or-nothing write transactions for any change that spans more than one file. Writes are classified by blast radius: a change to a single file is published by atomic replacement (temp file plus rename), which costs nothing measurable and guarantees no reader ever observes a truncated file; a change spanning several files — an entity rename and the connection files referring to it, a group move, a bulk write — is published through an M4 manifest, so the files land together or not at all. The distinction matters because a partially applied multi-file write leaves a repository that still parses and whose identifiers all still resolve, so nothing downstream reports it. Combines indexed reference-blocker lookups, tracked-path manifest derivation, overlay-backed verification, and copy-on-write staging when the extent of a change is not known in advance.
