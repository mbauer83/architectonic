## Update Installed Software

Bring an installed deployment from the version it runs to a published release: check what is published, verify the release and its assets, rehearse the next version's data upgrade against this deployment, then stop what serves, move the software, migrate the data, start what served and confirm the served version. Each step is recorded before and after it runs, so an interrupted update can be resumed or reversed, and a reversal restores data first, software second and the serving processes last. Distinct from Upgrade Repository Format, which it invokes: that process moves one repository's data to the format a version reads; this one moves the version.
