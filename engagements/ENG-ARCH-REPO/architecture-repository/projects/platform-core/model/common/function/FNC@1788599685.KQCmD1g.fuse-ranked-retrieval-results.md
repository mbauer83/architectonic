## Fuse Ranked Retrieval Results

Combine what several retrievers found into one candidate list using where each placed a candidate, never how strongly it scored it.

## Properties

| Attribute | Value |
|---|---|
| (none) | (none) |

## Notes

Keyword matching and vector similarity answer on scales that do not compare, so multiplying one into the other's range makes a number that means nothing. Position is the one thing they both express the same way, and a candidate both retrievers found ranks above one that a single retriever ranked first.

Two branches, and not the three this once said. Ranking by structural distance was built as a third input and measured against the labelled query suite: at equal weight it took the summary stratum from 98.3% to 61.7%, because a structural neighbour of the best answer counts for what the best answer counts for, and forty neighbours outvote the thing they surround. Weighted down far enough to stop that, it changed nothing. It may return, but only alongside per-branch weighting and a labelled stratum whose answer is not the relation it walks.

This produces the candidates; it does not order what a reader sees. That ordering is a separate policy earned by particular failures — an exact name match first whatever it scores, then entries carrying every term, then a rotation across kinds with a floor reserved so preliminary thinking never outranks committed content. A flat fused list in its place would discard all of it.

Where one branch contributes nothing for a query, combining still costs a little against using the better list alone. That is accepted: the queries where keyword matching is excellent are the common ones, and combining is what protects them.
