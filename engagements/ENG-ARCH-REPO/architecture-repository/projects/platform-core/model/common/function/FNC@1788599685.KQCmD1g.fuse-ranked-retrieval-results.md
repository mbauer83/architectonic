## Fuse Ranked Retrieval Results

Combine what several retrievers found into one candidate list using where each placed a candidate, never how strongly it scored it.

## Properties

| Attribute | Value |
|---|---|
| (none) | (none) |

## Notes

Keyword matching, vector similarity and structural distance answer on scales that do not compare, so multiplying one into the other's range makes a number that means nothing. Position is the one thing they all express the same way, and a candidate several retrievers found ranks above one that a single retriever ranked first.

This produces the candidates; it does not order what a reader sees. That ordering is a separate policy earned by particular failures — an exact name match first whatever it scores, then entries carrying every term, then a rotation across kinds with a floor reserved so preliminary thinking never outranks committed content. A flat fused list in its place would discard all of it.

Where one retriever contributes nothing for a query, combining still costs a little against using the better list alone. That is accepted: the queries where keyword matching is excellent are the common ones, and combining is what protects them.
