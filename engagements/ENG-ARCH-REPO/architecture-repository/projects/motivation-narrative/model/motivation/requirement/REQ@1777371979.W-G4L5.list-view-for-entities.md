## List-view for entities

The GUI frontend must provide a list-view for entities. This list must be filterable by archimate-domain and entity-type, as well as sortable by type and by number of connections (total, incoming, symmetric, outgoing).

A tree-like presentation — specialization, aggregation and composition children duplicated under each parent and indented — was previously required here and has been withdrawn. It is incompatible with pagination: a page is a window over an ordered population, and duplicating a child under every parent means a row's presence depends on whether its parent fell inside the window, so the same entity appears, vanishes or repeats depending on page size and sort order. The hierarchy it was meant to expose is served better by the graph-explore view, which shows those relationships as edges over a bounded neighbourhood rather than as indentation inside a paginated table.
