## Support Models, Diagrams, and Documents

The system shall support three primary artifact categories: architectural models (entities and their connections organized by ArchiMate 4.0 domains), diagrams (PlantUML visualizations referencing model entities), and documents (architectural decision records, guidelines, specification documents with structured cross-references). All three are held to one framework rather than three: one ID convention (`PREFIX@epoch.random.slug`, parsed by a single grammar), one verification infrastructure (a single `verify_all` pass reports on every category and needs no per-category entry point), and one frontmatter base — `artifact-id`, `artifact-type`, `version`, `status` and `last-updated` are required of every category and enforced by the same primitive, independently of any configurable per-file-type schema.

Amended 2026-08-02. The original text claimed all three share "the same frontmatter schema". They share the same base fields and the same mechanism, but not one schema, and the difference is deliberate rather than an omission. The human label is `name` for entities and diagrams and `title` for documents; each file type has its own configurable schema per REQ@1712870400.pSvaRl (`.arch-repo/schemata/frontmatter.{entity,outgoing,diagram}.schema.json`, and `.arch-repo/documents/{abbr}.json` for documents). Collapsing `title` into `name` would rename a field in every document in every repository to satisfy a phrase, and would make the vocabulary worse: a decision record has a title, an application component has a name. What the requirement is really about — that an author, a reader and a verifier meet one framework instead of three — is now stated in the terms that are true of the product, so it can be verified as written.
