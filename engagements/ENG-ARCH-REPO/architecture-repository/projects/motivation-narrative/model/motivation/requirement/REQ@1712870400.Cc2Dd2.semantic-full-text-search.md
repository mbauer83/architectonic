## Semantic Full-Text Search

The system shall let a reader find architectural artifacts — entities, connections, diagrams and documents — by describing what they are looking for, not only by naming it. Matching shall cover what an artifact is called, what it says about itself, and the fields it is filed under, so a query phrased in the reader's words reaches an artifact phrased in someone else's.

## Notes

Stated as what a reader can do, without naming what makes it work. The wording previously said the implementation "may use TF-IDF ranking or vector-based similarity, backed by the SQLite runtime index" — a requirement naming two mechanisms, one of which has since become untrue: vector similarity is served by a separate model and its own index, not by the runtime index. A requirement that names its mechanism has to be rewritten whenever the mechanism changes, and is wrong in the meantime.

What the requirement does need to say is the part a lexical index alone cannot do: reach an artifact whose wording differs from the query's. Measured on this repository, keyword matching answers a query that repeats an artifact's own name or summary almost always, and a query phrased in different words for the same thing almost never. That gap is what this asks for, and how it is closed is a decision recorded elsewhere.
