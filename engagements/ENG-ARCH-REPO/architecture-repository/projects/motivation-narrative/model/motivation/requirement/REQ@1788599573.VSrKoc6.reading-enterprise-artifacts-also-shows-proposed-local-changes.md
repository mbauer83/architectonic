## Reading Enterprise Artifacts Also Shows Proposed Local Changes

Wherever an engagement reads an artifact belonging to the enterprise tier, the system shall state alongside it whether local changes have been proposed against it and which of its fields those changes touch. A reader who cannot tell is working from content that looks authoritative and is not.

## Properties

| Attribute | Value |
|---|---|
| Category | Interface |
| Priority | Must |

## Notes

Two qualifiers carry the requirement and neither survives being dropped.

**Which fields.** A flag can say that something is proposed and never which parts, so a reader is told to distrust a whole artifact when one field is affected — and cannot see that its name is the enterprise's while its summary is a local suggestion.

**Wherever it is read.** One surface stating it is the failure this requirement exists to prevent rather than a partial success. The tier flag already carried on the same rows is emitted inconsistently across the read surfaces, which their contracts permit by declaring it optional — so a reader cannot tell "not flagged" from "this surface never says". Absence must not be expressible where its meaning would be "unchanged".

Byte surfaces are the deliberate exception. A rendered diagram, an exported model and a downloaded file carry no field for the statement, so they resolve to the enterprise content and report that they did, rather than showing proposed content a consumer would read as agreed.
