## Verified Software Update

An installed deployment can be brought to a published release by one command that proves what it installs before anything changes and leaves the deployment consistent whatever happens. The release is identified by the publisher's release record and its tag; the tag's signature, the release commit and every downloaded asset's digest are verified, and the next version's own data upgrade is rehearsed against the deployment's repositories and stores while the current version keeps serving. Nothing is written before those checks pass. A deployment that was serving is serving again afterwards on the same port with the same flags, and a store that was open is open again; a failure at any point returns the software, the data and the processes to the recorded prior state and says so. The same command reports its plan without acting, and behaves the same for a local checkout and a container deployment driven from its host.
