## Submit Proposed Changes for Review

Publish a chosen, ordered set of proposed changes for a reviewer to accept in the enterprise tier, and keep what was published knowable afterwards.

## Properties

| Attribute | Value |
|---|---|
| (none) | (none) |

## Notes

Ordered because several changes may address one artifact, and the order they are applied in decides the result. The order is part of what the proposer submits rather than inferred afterwards, so the same set produces the same content wherever it is replayed.

The step that reaches the reviewer cannot be taken back, and what is recorded locally about it is written before it rather than after. Whether it succeeded is then read from what the reviewer can see, not from the fact that a request returned — the two differ exactly when something failed in between, which is when it matters.
