## Reconcile Proposed Changes with a Moved Enterprise Tier

Say where each pending change stands once the enterprise artifact it addresses has moved on: it still applies, it has already been accepted, or it can no longer be applied and why.

## Properties

| Attribute | Value |
|---|---|
| (none) | (none) |

## Notes

Three answers rather than two, because "already accepted" and "cannot be applied" look alike from the outside and mean opposite things. Reporting an accepted change as a conflict asks its author to resolve their own merged work, which is the most confusing thing this function can say — so acceptance is decided first and nothing is replayed for a change that has already landed.

Where a change can no longer be applied, what is reported is the refusal the verifier itself gives. A second wording of the same refusal would be a second vocabulary for one fact, and the author acts on the verifier's.

Attempted somewhere disposable. A change has to be applied to know whether it still applies, and applying it where a reader is looking leaves the failure behind — so the attempt happens on a copy that is discarded whatever it concludes.
